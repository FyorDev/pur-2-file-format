# Investigation archive

Synthetic fixtures and historical experiments used to derive the format. These
are development evidence, not inputs required by the library or writer.

- `00`–`05`: app-generated image and resave experiments.
- `10-from-scratch.pur`: intentionally incorrect early checksum experiment.
- `12-valid-scratch.pur`: corrected independently written image canvas.
- `20-note-only.pur`, `21-group.pur`, `22-drawing.pur`, `23-line.pur`:
  authentic UI-generated note, group, and drawing fixtures.
- `20-note.pur`: the evolving canvas, eventually containing the combined tests.
- Tiny PNG/JPEG files: synthetic image inputs for regression tests.
- `EVIDENCE.json`: hashes of the original experiments and installed app binary.
- `binary-relevant-strings.txt`, `command-help.txt`, and intermediate renders:
  historical investigation material.

The original fixtures retain historical source-path metadata. They contain only
synthetic content. Preserving their exact bytes allows regression tests to check
the independently derived container/checksum algorithm.

Machine-specific `.ini` settings, raw `.log` files, bytecode, and full historical
`validation-*` output directories are preserved in the local copy but ignored by
Git. A compact historical summary is checked in as `VALIDATION.json`.

Run tests from the repository root:

```sh
python -m unittest discover -s tests -v
python -m investigation.validate
```

The integration suite requires PureRef. Set `PUREREF_EXE` if it is not installed
at `C:\Program Files\PureRef\PureRef.exe`. It creates fresh `validation-*`
directories with isolated settings; it does not read personal canvases.

`python -m investigation.make_fixtures` regenerates the CLI-created fixtures;
their original hashes will consequently change. UI-created fixtures are retained
as evidence and are not regenerated by that script.
